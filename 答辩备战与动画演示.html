答辩老师必考 5 大硬核问题（通俗易懂大白话拆解）
Q1 为什么要用“环形缓冲区”？直接在串口中断里处理数据不行吗？
▼
🍔 零基础大白话比喻：
中断函数就像“快递员”，主程序就像“收件人”。
如果不用缓冲区，快递员送货时必须强迫收件人当场签收并拆开查看。如果收件人正在做别的事（比如机器狗正在做俯卧撑动作延时 2 秒），快递员就被卡在门口死等，后面送来的其他快递（串口数据）就全部丢在大街上了（丢包/系统卡死）。
有了环形缓冲区：就像在门口放了一个“智能快递柜/传送带”。快递员丢下快递只需要 1 微秒，立马就走；机器狗做完动作空闲了，自己去快递柜里一件件拿出来处理。

答辩标准话术避免中断阻塞 · 解耦 CPU 耗时动作 · 防止数据丢包

  1. 避免中断阻塞：中断服务函数（ISR）必须“即收即走”。如果在中断里做复杂的字符对比或等待延时，会卡死 CPU，导致舵机 PWM 等其他中断无法响应。
  2. 解耦主程序延时：机器狗步态控制有延时，通过环形队列将数据暂存，实现了串口接收与业务解析的解耦。
Q2 环形缓冲区是怎么判断“空”和“满”的？满了怎么办？
▼
🏃 零基础大白话比喻：
把缓冲区想象成一个128 格的环形跑道。
• 写指针 `s_head`：快递员放货的位置。
• 读指针 `s_tail`：收件人取货的位置。
• 怎么算空？两个人站在同一个格子上（head == tail），说明货物拿光了。
• 怎么算满？快递员跑了一圈，快从屁股后面追上收件人了（(head + 1) % 128 == tail）。为了防止把还没拿走的货物踩烂（覆盖旧数据），必须空出一个格子并停止写入。

答辩标准话术读写指针比对 · 浪费一空间判满 · 保护既有数据

  • 判空公式：s_tail == s_head。
  • 判满公式：(s_head + 1) % 128 == s_tail。采用“浪费一个存储单元”算法。
  • 满了的处理：放弃写入新字节，保护已有数据不被覆盖。因为缓冲区有 128 字节，消费极快，实际测试中没有发生溢出。
Q3 无线通信联调测试中，你遇到了什么踩坑问题？怎么解决的？（老师最爱问）
▼
🛠️ 零基础大白话比喻：
坑 1（消息被切断）：蓝牙发消息就像发微信，有时因为信号不好，原本的“STAND”（立正）被切成了“ST”和“AND”两次发过来。我们在环形缓冲区里把它们拼完整了才让机器狗做动作。
坑 2（串口死锁）：高频发消息时，串口硬件有时会陷入“死机卡死”（ORE 溢出）。我们在中断代码里加了“检测到卡死就自动重启擦除”的代码，让串口永远不会死机。

答辩标准话术拆包粘包处理 · ORE 硬件溢出自动恢复

  1. 无线拆包/粘包排查：通过环形缓冲区暂存字符，配合换行符/结束符校验，确保拼接出完整指令帧后再交给机器狗执行。
  2. ORE 溢出锁死清除：中断中检测 USART_FLAG_ORE，主动调用 USART_ReceiveData 读取擦除标志，保证串口不卡死。
Q4 代码里的 `volatile` 关键字有什么用？为什么 `s_head` 和 `s_tail` 必须加它？
▼
📝 零基础大白话比喻：
CPU 芯片非常聪明但也非常懒！它喜欢把变量抄在自己口袋里的“便条纸”（寄存器缓存）上，不肯每次都跑到内存墙（RAM）去看。
问题来了：中断把内存墙上的 `head` 指针改了，但主程序还在傻傻看自己口袋里的便条纸，以为没有新消息。
`volatile` 的作用：就是严厉警告 CPU：“不许看你自己口袋里的便条纸！每次必须亲自抬头看内存墙！” 这样中断一改，主程序立刻就能看到！

答辩标准话术防止编译器优化缓存 · 强制内存实时读写 · 保障中断共享变量安全

Q5 无线通信模块型号、波特率、数据帧格式是怎样的？
▼
  • 模块与波特率：HC-05/HC-08 蓝牙透传模块，连接 STM32 的 USART3/USART1，波特率 9600 bps (8N1)。
  • 上行数据帧（STM32 → 电脑）：DATA,T=25.3,H=60,L=80（每 500ms 发一次健康报告）。
  • 下行控制帧（电脑 → STM32）：FWD（前进）、STAND（立正）、SIT（坐下）、FACE=1（切表情）。文本协议简单好调！

`link.c` 核心环形缓冲区与串口中断源码
/* ==============================================================================
 * 串口环形缓冲区实现 (HARDWARE/LINK/link.c)
 * 作用：多串口中断接收合并、防丢包、解耦 CPU
 * ============================================================================*/
#define LINK_BUF_LEN    128

static volatile uint8_t  s_buf[LINK_BUF_LEN];  // 数据环形数组
static volatile uint8_t  s_src[LINK_BUF_LEN];  // 串口来源标记 (1=USART1, 3=USART3)
static volatile uint8_t  s_head = 0, s_tail = 0; // volatile 内存写读指针

// 入队函数：在 USART 中断函数中被调用
static void link_push(uint8_t ch, uint8_t src_port)
{
    uint8_t next = (uint8_t)((s_head + 1) % LINK_BUF_LEN);

    if (next != s_tail) // 判满：如果下一个位置不等于读指针，说明未满
    {
        s_buf[s_head] = ch;
        s_src[s_head] = src_port;
        s_head = next;   // 推进写指针
    }
}

// 出队函数：在 main.c 主循环中被调用
uint8_t LINK_GetCharEx(uint8_t *src_port)
{
    uint8_t ch = 0;
    if (s_tail != s_head) // 判空：读写指针不相等即有数据
    {
        ch = s_buf[s_tail];
        if (src_port != 0) *src_port = s_src[s_tail];
        s_tail = (uint8_t)((s_tail + 1) % LINK_BUF_LEN); // 推进读指针
    }
    return ch;
}

// 串口中断服务函数与 ORE 溢出清除
void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        link_push((uint8_t)USART_ReceiveData(USART1), 1);
    }
    if (USART_GetFlagStatus(USART1, USART_FLAG_ORE) != RESET) {
        (void)USART_ReceiveData(USART1); // 读取擦除 ORE 标志位，防止死锁
    }
}
